# ============================================================================
# 4. EMULATOR -- REQUIRED (Renode, NOT pip-installable)
# ============================================================================
# The multi-node ring launches N headless Renode instances. Each creates its own
# PTY at /tmp/haven_uart_<id>.
#
# Verified working: Renode v1.16.1  (binary: /usr/bin/renode)
#
# Install (this is the reliable route):
#   1. Download the portable .deb / .tar.gz from:
#        https://github.com/renode/renode/releases
#   2. Or use snap:
#        sudo snap install renode
#   3. Or build from source (slow):
#        sudo apt install mono-complete mono-devel
#        git clone https://github.com/renode/renode.git
#        mkdir renode/build && cd renode/build
#        ./configure --disable-dependency-tracking
#        make -j$(nproc)
#
# Verify:
#   renode --version          # must print a version
#   which renode              # must resolve on PATH used by haven_ring.conf
#
# IMPORTANT runtime detail:
#   start_haven.sh passes `--port -1` to every instance. Without it, each
#   Renode process tries to bind monitor port 1234 and all but the first die
#   with "Address already in use" -- and never create their PTY, so the ring
#   silently forms partially. This is already handled in haven_ring.conf
#   (RENODE_FLAGS). Do not remove --port -1.


# ============================================================================
# 5. ns-3 -- REQUIRED FOR THE NEXT PHASE (NOT pip-installable, NOT installed)
# ============================================================================
# STATUS: NOT YET INSTALLED ON THE REFERENCE MACHINE. Nothing in the current
# working code path requires ns-3. The current ring (start_haven.sh +
# bridge/ring_switch.py) runs entirely in Renode with no ns-3 involvement.
#
# ns-3 is the C++/Python discrete-event network simulator that will replace the
# Python relay in bridge/ring_switch.py so it can model packet loss, delay and
# bandwidth. See plan.md for the full design.
#
# ---- IMPORTANT CORRECTION -------------------------------------------------
# The previous discussion assumed ns-3 had a native ZMQ co-simulation module.
# IT DOES NOT. Verified against the upstream repo (nsnam/ns-3-dev-git):
#   * `contrib/` contains only a .gitignore -- no zmq contrib module.
#   * `src/` has NO zmq module. The closest are `fd-net-device` and
#     `tap-bridge` (both need root/TAP) and `bridge` (L2 bridging).
#   * `examples/` has no zmq example.
# ns-3's supported external-simulator integration paths are therefore:
#
#   (A) TAP / veth bridge  -- `src/tap-bridge` (TapNetDevice).
#       Requires CAP_NET_ADMIN to create /dev/net/tun interfaces.
#       BLOCKED for the reference user: uid=1000, CapEff=0 (no capabilities).
#       Would need root or a capabilities grant.
#
#   (B) Write a thin ns-3 module/application that links libzmq directly.
#       ns-3 is a normal C++ library set; you can link any C/C++ dependency.
#       Install libzmq3-dev, then write a small ns-3 application that opens a
#       ZMQ socket per emulated node. This is the RECOMMENDED path for this
#       project because it needs no privileges and keeps ns-3 in charge of
#       time/loss modelling.
#
#   (C) NIST ns3-cosim (https://github.com/usnistgov/ns3-cosim)
#       Uses a TCP/IP socket gateway, NOT ZMQ, and is pinned to a V2X fork of
#       ns-3 (ns-3-dev-v2x-v1.1), not stock ns-3. Heavier than needed here.
#
# If you go with (B), the Python bridge already has pyzmq available (see below)
# so only the ns-3 side needs libzmq C bindings.
#
# ---- Install instructions --------------------------------------------------
# Stock ns-3 (recommended if following path (B)):
#   git clone https://gitlab.com/nsnam/ns-3-dev.git
#   cd ns-3-dev
#   ./ns3 configure --enable-examples --enable-tests
#   ./ns3 build
#   ./ns3 run hello-simulator        # smoke test
#
# Dependencies for building ns-3:
#   sudo apt install build-essential cmake ninja-build git python3 python3-pip \
#                    g++ pkg-config libxml2-dev libsqlite3-dev qtbase5-dev
#
# Python-side helper libs used by the planned ZMQ bridge:
#   pyzmq>=4.6          # ZMQ sockets from Python. Verified: 27.1.0 installed.
#   pybind11>=2.10      # needed only if using ns-3 Python bindings. NOT installed.
#
# System-side ZMQ for the ns-3 (C++) side, path (B):
#   sudo apt install libzmq3-dev
#
# Disk warning on the reference machine:
#   / is 95% full (only ~4.7 GB free). Building ns-3 from source typically needs
#   2-4 GB. Free space or build on another volume BEFORE running ./ns3 build.
#   Check with: df -h /
#
# Do NOT rely on `apt install ns3` -- that is ns-3 3.35 (2019), which predates
# all modern build tooling and has no ZMQ path.
